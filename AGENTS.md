# AGENTS.md — Repo Context

## What This Repo Is
Personal GitHub Pages site (`mihir-kale.github.io`). Static HTML + Supabase backend. No build step, no package.json, no framework. Deploys automatically on push to `main`.

## Structure
- `portfolio/` — Landing page (HTML + CSS, Inter font, profile photo)
- `dashboard/` — "Personal OS" single-page app
  - `index.html` — monolithic: all HTML/CSS/JS in one file (~2760 lines)
- `media/` — Commonplace book: `index.html`, `styles.css`, `js/app.js|covers.js|data.js|auth.js|spotify.js`, `data/library.json`, `data/feed-sources.json`, `data/feeds.json`, `scripts/add_media.js`, `scripts/push_media.mjs`, `scripts/sync_feeds.mjs`, `scripts/spotify_auth.mjs`, `.github/workflows/sync-feeds.yml`. Curated entries live in the Supabase `media_entries` table (read by `loadEntries()` in `js/data.js`, which falls back to `data/library.json` if the backend is unreachable); RSS short non-fiction/podcasts load from `data/feeds.json`; both merge in `js/app.js`. Cache-busting: `index.html` loads `js/app.js?v=YYYYMMDD` and every internal import (`data.js`/`covers.js`/`auth.js`, and `auth.js`→`data.js`) carries the same `?v=` — bump that version string on every JS change so clients don't run stale modules against changed data. `scripts/push_media.mjs` (dependency-free Node, service-role key from `.env`) upserts `library.json` into `media_entries`. `scripts/sync_feeds.mjs` (dependency-free Node) fetches `feed-sources.json`, parses RSS/Atom, excludes promo/coupon titles, caps per source, and rewrites `feeds.json`; a scheduled GitHub Action (`.github/workflows/sync-feeds.yml`, daily + `workflow_dispatch`) runs it and commits changes. Feed items always get `list: "shelf"`, `mediaType` from their source, and `source: "feed"`; the shelf displays at most 5 items per category (`SHELF_LIMIT` in `js/app.js`); short non-fiction/podcasts arrive via feeds, though manual entries (e.g. a recommended book) can be added with `scripts/add_media.js --list recommend`. Each shelf feed item has a small `×` (dismiss) that hides it via the Supabase `media_marks` table (keyed on the stable feed item id; `localStorage` under `media:dismissed:v1` is a local cache/fallback) plus a checkbox that promotes it into "my recommendations" (same `media_marks` row, `promoted` column; `media:promoted:v1` is the local fallback; the item renders in the recommend view — checked, no `×` — and unchecking sends it back to the shelf). Backend tables: `media_entries` (public read, owner/authenticated write), `media_marks` (public read + anon insert/update), and `media_suggestions` (the "recommend me something" form, anon insert-only). Owner sign-in (`js/auth.js`, email/password against Supabase Auth over REST — sessions cached in `localStorage` under `media:session:v1`, refreshed near expiry) reveals in-place editing: signed-in, every curated (`source !== "feed"` and `!== "suggestion"`) entry gets `edit`/`del` controls and the topbar shows `+ new`; both open a `<dialog>` editor (category, title, creator, year, status, consumed, list, url, tags, notes, spotlight) that writes to `media_entries` via `saveEntry`/`deleteEntry` in `js/data.js`; signed-out visitors get the read-only board — per-type rails styled like reading lists (fiction · non-fiction · short fiction · short non-fiction · films · music · podcasts) packed masonry-style: `js/app.js` measures each rail and drops it under the shortest column with a fixed gap, recomputing on resize. A global top-bar toggle switches every category rail between `list: "recommend"` (default) and `list: "shelf"` (the toggle iterates `TOGGLE_LISTS` in `js/data.js`, not all of `LISTS`); each `media_entries` row carries a `list` field, and a third value `now` (offered in the editor's list dropdown, DB check constraint relaxed in `supabase/migrations/20261012000000_media_now_list.sql`) drives a special always-visible rail pinned above the category rails and unaffected by the toggle: `buildNowRail()` in `js/app.js` renders it headerless, tinted like a rail header (`--head`), grouped as "currently reading / watching / listening to" (`NOW_GROUPS`), always lowercase, showing "nothing here yet" when empty. The "currently listening to" group is topped by a live Spotify line (latest track, no album art): `js/spotify.js` polls the public `now-playing` Supabase Edge Function (source in gitignored `supabase/functions/now-playing/index.ts`; secrets `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET`/`SPOTIFY_REFRESH_TOKEN`) every 30s and silently falls back to curated listening items if unavailable; the one-time owner refresh token is produced by `media/scripts/spotify_auth.mjs` (PKCE, redirect `http://127.0.0.1:8888/callback`) and stored via `supabase secrets set`, so the client secret never ships to the browser. All seven category rails always render, showing "nothing here yet" when empty. Search and spotlight-first ordering; no rating display. Also includes a "recommend me something" form rail (category dropdown, required title, why) that is always visible: on submit it POSTs to the Supabase `media_suggestions` table (anon insert-only RLS, no anon read; public anon key hardcoded in `js/data.js`, tables defined in gitignored `supabase/migrations/`) submissions are read back by the signed-in owner only (`loadSuggestions()` in `js/data.js`; RLS grants select to `authenticated`) and land on the matching **shelf** rail as `source: "suggestion"` entries, pinned above the `SHELF_LIMIT` cap so feed items can't push them out; signed-out visitors never see them. Types: `fiction`, `non-fiction`, `short-fiction`, `short-non-fiction`, `film`, `album`, `podcast` (`article`/`essay`/`book`/`tv` retired; reading entries were migrated article/essay → short-non-fiction and book → non-fiction, so re-tag fiction via edit). For `fiction`/`non-fiction`/`film`/`album`/`podcast` entries in `list: "recommend"` only, `js/covers.js` (`resolveCover`, with a `tmdb-api-key` meta) resolves cover art async — any Spotify link via the oEmbed thumbnail, otherwise Google Books + Open Library for books (queried by the main title, with any subtitle after `:`/dash stripped), TMDb for films, iTunes for albums and podcasts (podcast show name trimmed of `|`/`—` decorations) — rendered as a thumbnail on the right of the entry with the text squeezing left; shelf entries and entries with no image found stay full-width and text-only. Notes are clamped to two lines with a "more…" control that expands the entry; "more…" is hidden when the note already fits. Negative cover lookups are cached too. Light/dark theme: `data-theme="dark"` on `<html>` (applied pre-paint by an inline `<head>` script reading `media:theme:v1`) flips the CSS custom properties in `styles.css`; the top-bar `#themeToggle` button in `js/app.js` (`setupTheme()`) toggles it and persists the choice.
- `.env` — secrets (gitignored)
- `supabase/` — gitignored (migrations)

## Dashboard App Details
- **Backend**: Supabase. Tables: `tasks`, `projects`, `people`, `calendar_events`
- **Auth**: Email/password via Supabase Auth (`signInWithPassword`). RLS gates all real data. Signed-out visitors get demo mode: the real dashboard preloaded with hardcoded sample data (via `loadDemoData()`), so every control — filters, Projects toggle, calendar, drag-drop — behaves exactly like the live app. While signed out nothing is fetched from or written to Supabase; edits mutate in-memory arrays only (`demoMode` guards every loader/write path).
- **Calendar**: Reads `calendar_events` table + live feed from the `calendar-proxy` edge function. Feed rows come from Outlook/Google, persist via RPC `sync_calendar_feed`, and dedupe by `external_id`. Each row has a `source` (`'feed'` = read-only, `'manual'` = editable time block).
- **Features**:
  - Tasks: title, due date, project, people, description, recurrence (daily/same-day weekly). No priority on tasks (projects keep priority).
  - Calendar: Day/Week views, time-blocking, feed events (read-only), recurrence for manual blocks, drag task→calendar to create a 1h block, drag calendar event→tasks creates a `TODO:` task, drag block→reschedule.
  - People: name, contact, last contact, description; multi-tag onto tasks/projects.
  - Projects: name, priority (low/medium/high/urgent), status (pending/done), people, description; bundles its tasks.
  - "NOW" panel (mobile): next imminent event or next active task.
  - Demo mode (signed-out): the real `#os` dashboard with sample tasks/projects/people/events from `demoTasksData()`/`demoProjectsData()`/`demoEventsData()`; topbar shows `#signInBtn` + `#tourBtn` and a `#demoBanner` notice, Projects hide toggle works. Feature tour (`TOUR_STEPS`) targets real panels (`#projectsPanel`, `#tasksPanel`, `#calPanel`). `demoMode = !signedIn` set in `applyAuthState()`; guarded writes snapshot to local STATE arrays and re-render.
- **Theme**: Light/dark mode (CSS custom properties, `data-theme="dark"` on root, persisted in localStorage under `personalOSTheme`).
- **Timezone**: `America/New_York` (constant `TZ`).
- **No frameworks** — vanilla JS, vanilla CSS, monospace font aesthetic.

## Key Patterns
- All JS is inline in a `<script>` tag at the bottom of `dashboard/index.html`.
- Supabase client initialized with hardcoded `SUPABASE_URL` + `SUPABASE_ANON_KEY` in JS (anon key is public by design; RLS protects data).
- Date helpers use `toLocaleDateString('en-CA', { timeZone: TZ })` for YYYY-MM-DD; `todayEt()`, `addDaysLocal()`, `weekStartOf()` (Monday start).
- IDs are nanoid-generated client-side via `crypto.getRandomValues`.
- Hidden events persisted in localStorage under `personalOSHiddenEvents`; `evKey()` = `ext:<external_id>` for feed, `id:<id>` for manual.
- Escaping via `escapeHtml()` on all innerHTML interpolation.
- Recurring manual blocks: DB stores an anchor row; render-time `expandRecurring()` clones virtual occurrences into the visible range. DB row never mutated.
- Drag-and-drop for tasks and calendar blocks.
- Other localStorage keys: `personalOSProjectsOpen`, `personalOSPeopleCollapsed`.
- Realtime: `postgres_changes` on `tasks` (if in realtime publication) + 60s task / 5min calendar polling fallback.

## Don'ts
- Don't add npm/node/build tooling or frameworks.
- Don't commit `.env` or `supabase/`.
- Don't expose secrets (Supabase anon key is public by design).
- Feed events (`source === 'feed'`) are read-only — never edit them in the DB.
